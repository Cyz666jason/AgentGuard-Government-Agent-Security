# AgentGuard 项目最新进展（截至 2026-08-20）

> 本文用于统一说明当前做到了什么、证据覆盖到哪里、哪些内容尚未完成，以及下一步如何推进。所有路径均为仓库相对路径，不包含凭据、个人信息或本机绝对路径。

## 一、总体结论

AgentGuard 已经完成“可信身份 → OPA 三态决策 → 人工审批 → 强制阻断网关 → 一次性执行票据 → Wasmtime 安全内核 → 受控业务适配器 → 审计”的测试级闭环，并补充了 OpenBao 共享状态、QEMU 独立来宾内核、OPA-Envoy/ToolHive 容器链路和 OpenClaw 只读 MCP 接入。

当前可以准确表述为：**当前代码和已定义测试场景通过，核心安全控制链已形成可复现原型；项目尚未达到生产就绪。** `reports/status/status_consistency_check.json` 的 8/8 状态一致性检查通过，并确认所有汇总材料中的 `production_ready` 均为 `false`。

远程仓库已由 `reports/status/github_publication.json` 验证为公开可读。该结论只说明仓库可见性，不代表最新工作区天然已经同步，也不代表系统已通过生产验收；具体同步状态应以最新远程提交和对应 CI 结果为准。

### 2.4 OpenClaw 最小接入

原系统只有自定义 REST、内部 Python 模块和 CLI，没有标准 MCP Server，因此原始状态不能零改造接入 OpenClaw。目前已增加一个薄型 stdio MCP 适配器，只暴露低风险只读工具 `list_notices`，模型只能提供 `limit`，不能指定身份、资源、审批结果或执行目标；所有调用固定进入 AgentGuard `/invoke`，继续经过身份、OPA、一次性票据、Wasmtime 和审计。

已完成 OpenClaw 2026.7.1-2 实机注册、`doctor --probe` 和工具发现，OpenClaw 只发现 `agentguard-notices__list_notices`。确定性 MCP 客户端还实际执行了 `initialize → tools/list → tools/call`，返回 2 条隔离测试公告且 `side_effect=false`。主证据为：

- `reports/e2e/openclaw/openclaw_mcp_integration.json`
- `reports/e2e/openclaw/openclaw_mcp_integration.md`
- `reports/e2e/openclaw/openclaw_mcp_protocol_probe.json`

必须明确：OpenClaw 探针证明了实机连接和 `tools/list`；低风险 `tools/call` 由确定性协议客户端执行。由于没有获批的模型凭据，尚未运行 OpenClaw agent 模型回合，因此不能写“OpenClaw 模型已经自主调用工具”或“生产接入完成”。

## 四、当前测试边界

1. 测试结果只覆盖当前代码版本、当前测试机/CI 环境和已定义场景，不证明系统绝对安全。
2. Keycloak 使用本机 HTTP 开发测试域和合成 MFA claims，未验证生产 HTTPS、组织目录联邦和真实 OTP/WebAuthn。
3. 容器 E2E 来自 GitHub Actions Linux Runner；本机无容器运行时。对应 CI 证据产生后仓库又有变更，因此新提交需要重新运行 CI 才能覆盖最新代码。
4. OpenBao HA 是同机多进程验证；未完成跨故障域、TLS、自动解封、快照恢复、网络分区和容量压测。
5. QEMU 证明了独立来宾内核边界，但使用 TCG；尚未完成 Linux/KVM 上的 Kata 或 Firecracker 产品实测与性能对比。
6. 业务执行对象和公告数据均为隔离测试数据；没有真实业务系统凭据，也没有获批生产日志。
7. 公开基准只完成适配器合同测试，不能把自编 fixture 写成 AgentDojo、InjecAgent 或 AgentHarm 的真实成绩。
8. OpenClaw 已完成实机注册和工具发现，但没有执行带模型凭据的 agent 回合，也没有验证逐用户身份和单位网络零旁路。
9. 发布前扫描结果只说明扫描规则未发现已定义的敏感模式，仍需代码评审、依赖扫描、制品签名和持续 CI 门禁。

## 六、下一步执行顺序

1. **先完成发布闭环**：对当前变更重新运行发布前扫描和状态一致性检查，推送后等待 GitHub Actions 完成，并记录覆盖当前提交的 CI 证据。
2. **补 OpenClaw 模型回合**：在隔离环境使用获批模型凭据和低权限测试用户，验证工具选择、身份绑定、只读调用、拒绝路径和完整审计；仍不开放写入工具。
3. **补生产身份与网络零旁路**：实现 requester-scoped OIDC/OAuth、内部 CA/mTLS、NetworkPolicy/防火墙和后端票据核销，禁止 Agent 主机直接访问业务数据库、业务 API 与通用 shell。
4. **进入阶段 4 外部产品验收**：优先安排 Linux/KVM 的 Kata/Firecracker，对跨故障域 OpenBao 和 Kubernetes 做故障注入，再验证 Keycloak HTTPS/HA/真实 MFA。
5. **取得授权后再接真实系统和数据**：从只读业务查询开始，完成脱敏、回放和对账；写入、付款、发布和运维能力逐个建立窄 API、审批规则、幂等/补偿和负面测试。
6. **扩展真实数据评估**：导入许可允许的公开基准，补并发审批、跨步骤攻击、编码混淆、提示注入和生产日志回放，同时保留独立分母与测试环境说明。
